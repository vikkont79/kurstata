# Kurstata

Учёт рабочих смен: ввод данных по дням (смены, часы, заказы, выручка) и сводка по неделям.

**Живое приложение:** [kurstata.ru](https://kurstata.ru)

## Возможности

- **Демо-режим** — главная страница показывает работу приложения на примерных данных и доступна без регистрации; клик по любому элементу ведёт на форму входа
- **Дашборд** — сводка по неделям с метриками (часы, заказы, заказы/час, суммы) и переключением периода: неделя / месяц / всё время
- **Ввод дня** — смены (время начала/конца, заказы), сумма за день; черновик формы сохраняется локально и не теряется при закрытии вкладки
- **Редактирование и удаление** дней
- **PWA** — устанавливается на телефон как приложение ([манифест](public/manifest.json))

## Стек

- [Next.js](https://nextjs.org) 16 (App Router) + React 19
- TypeScript (strict)
- Tailwind CSS 4
- [Drizzle ORM](https://orm.drizzle.team) + [Turso](https://turso.tech) (libSQL)
- React Hook Form + Zod
- Upstash Redis — rate limiting (скользящее окно)
- Resend — доставка писем
- Аутентификация: bcrypt + JWT в httpOnly-cookie

## Требования

- Node.js 22+
- pnpm

## Установка

```bash
pnpm install
```

Создать `.env` по образцу `.env.example` и заполнить переменные.

## Переменные окружения

| Переменная | Описание |
|---|---|
| `TURSO_DATABASE_URL` | URL базы Turso (`libsql://...`) |
| `TURSO_AUTH_TOKEN` | Токен доступа Turso |
| `JWT_SECRET` | Секрет подписи JWT-сессий, минимум 32 символа. Сгенерировать: `openssl rand -base64 32` |
| `UPSTASH_REDIS_REST_URL` | URL REST API Upstash Redis |
| `UPSTASH_REDIS_REST_TOKEN` | Токен Upstash Redis |
| `RESEND_API_KEY` | Ключ API Resend (опционально). Без него письма печатаются в консоль вместо отправки |

Конфигурация окружения валидируется при старте (`src/shared/lib/env.ts`) — при ошибке приложение падает с понятным сообщением. При недоступности Redis rate limiting работает в fail-open режиме (пропускает запросы).

## Архитектура

Feature-Sliced Design:

- `src/app/` — роутинг Next.js (layout, page)
- `src/sections/` — сборка страниц (дашборд, демо, добавление дня)
- `src/widgets/` — крупные блоки (шапка, список недель)
- `src/features/` — пользовательские сценарии (авторизация, ввод дня)
- `src/entities/` — бизнес-сущности (пользователь, день)
- `src/shared/` — переиспользуемое (UI, API, утилиты)

Весь бэкенд — server actions без REST-роутов. Каждый action следует одному шаблону: валидация Zod → rate limit → бизнес-логика → дискриминированное объединение результата.

## Авторизация

Email + пароль, все операции — через server actions.

- **Регистрация** — подтверждение по одноразовому 6-значному коду (OTP). Данные регистрации до подтверждения живут в Redis с TTL 15 минут и в БД не появляются; код ограничен 5 попытками ввода
- **Сессия** — JWT (7 дней) в httpOnly-cookie; logout отзывает все сессии серверно (счётчик `token_version`)
- **Защита от подбора** — per-IP блокировка: после 5 неудачных попыток с одного IP (`ip:email`) этот IP блокируется на 15 минут; аккаунт при этом не блокируется, попытки чужих IP не влияют на вход владельца. Регистрации и запросы сброса лимитируются отдельно (per-IP)
- **Восстановление пароля** — одноразовая ссылка на email: токен хранится в БД только в виде SHA-256, срок действия 30 минут; после смены пароля выполняется автовход и отзыв прежних сессий
- **Приватные маршруты** (`/dashboard`, `/add`) защищает proxy: проверяет подпись JWT и живость сессии по `token_version` в БД
